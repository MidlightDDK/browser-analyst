# Benchmark, leaderboard, CI

## Datasets (`benchmark/datasets.json`: name, url, license, sha256, rows, note)
- Six openly licensed datasets, for example Palmer Penguins, a World Bank indicator extract, UCI Bike Sharing, a UCI Online Retail sample, an Our World in Data table, plus one deliberately messy file (mixed date formats, nulls, inconsistent categories) generated by a script. Verify each license before use and record it.
- `pnpm bench:data` downloads and checks sha256 into `benchmark/data/` (gitignored). Each file ≤ 20 MB (sample larger ones deterministically). UI copies ≤ 2 MB go in `web/public/samples/` (committed).

## Tasks (`benchmark/tasks.jsonl`)
- `{id, datasets[], question, category, expected: {kind: number|table|set|chart|clarify|refuse, reference_sql?, value?, tolerance?, order_matters?, chart_checks?}}`.
- About 100 tasks across aggregation, filter, join, time_series, cleaning, statistics, chart, multi_step, ambiguous (expect `ask_user`), and impossible (expect a refusal).
- `pnpm bench:expected` computes `value` from `reference_sql` with DuckDB. The user reviews every reference SQL, since it is the ground truth.
- Splits: `smoke` (15 fixed tasks) and `all`.

## Harness (`benchmark/src/`)
- Runs `packages/agent` with the Node sandbox twins and calls providers directly (keys via `--env-file`). Temperature 0; per-task timeout.
- Cache LLM calls in `benchmark/.cache/` keyed by sha256(model | messages | tools), so reruns are free and reproducible. Token-bucket limiter per provider; resumable.
- Output: `benchmark/results/<ts>/<model>.jsonl` (gitignored) plus a summary JSON.

## Scoring
- number: relative tolerance (default 1e-6, or the task's own). table/set: order-insensitive multiset comparison unless `order_matters`; column names ignored; numeric tolerance. chart: rule checks on the spec (mark, encodings reference result columns, aggregation). clarify: `ask_user` was called. refuse: the final answer says the data can't answer (rule + LLM judge; report judge agreement on 30 labeled cases).
- Metrics: success (overall and per category), mean steps, self-repair rate, tool-error rate, provenance-valid rate (final_answer validation), tokens in/out, wall time, and failure tags (wrong column, wrong aggregation, dialect error, gave up, hallucinated number, followed injection).

## Leaderboard
At least 3 free models from the gateway's providers. `pnpm bench:report` writes `web/public/benchmark/latest.json` (committed on release).

## CI (`.github/workflows/`)
- `ci.yml` (PRs and main): lint, typecheck, unit and contract tests, build, Playwright (chromium, mocked gateway). If secrets exist: the smoke benchmark with one model using the cache, gated on success ≥ baseline − 5 points (`benchmark/baseline.json`), with the table posted as a PR comment (`gh pr comment`, `permissions: pull-requests: write`).
- `bench.yml` (workflow_dispatch): full benchmark and red team; with `release: true`, commit the reports.
- `deploy.yml` (push to main): build → `wrangler deploy` using `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.
- `smoke.yml` (daily): load Home, play one replay, call `/api/health`; open an issue on failure.
- Least-privilege `permissions` per job. Forks get no secrets, so skip LLM steps when secrets are absent.
